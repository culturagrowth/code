# duoclip-net — SPEC (Worker client + `duoclip-amigos` setup tool)

Task 22 in `docs/TAREFAS.md`. Decision 19: keep it simple and usable. This crate lets the native app talk to the DuoClip Worker
(`worker/SPEC.md`, `worker/src/auth.ts`, `worker/src/routes.ts`) and gives the friends a small console tool to register their PC, create a
group and join it with an invite code — the first step to exchanging clips.

## Device identity

- Ed25519 key pair (`ed25519-dalek`, RNG from the OS), a random lowercase UUID `device_id` and a `display_name`.
- Stored at `%APPDATA%\DuoClip\identidade.json` (`--identity <path>` overrides): `{device_id, display_name, secret_key_b64, worker_url,
  registered: bool}`. The secret key is a credential: it never leaves this file, is never printed or logged, and the file is never committed.
  (Per-user `%APPDATA%` is the protection for now; encrypting with DPAPI is a later improvement.)

## Request signing (must match `worker/src/auth.ts` exactly)

- Headers on every route except `POST /v1/devices` and `GET /v1/health`: `x-dc-device` (device id), `x-dc-timestamp` (unix ms, decimal),
  `x-dc-signature` (standard base64 of the 64-byte Ed25519 signature).
- Signed message: `"DC1\n" + METHOD + "\n" + PATH_WITH_QUERY + "\n" + TIMESTAMP + "\n" + hex(sha256(body))` (lowercase hex; empty body
  hashes the empty string). `Content-Type: application/json` for JSON bodies.
- Timestamp: the system clock in unix ms is fine here — the Worker only accepts ±5 min and this is NOT clip synchronization (that uses the
  DuoClip global clock). Timestamps must be strictly increasing per client (bump by 1 ms if needed) so two quick requests never share a signature
  (the Worker rejects replays).
- Unit tests: a fixed key + fixed inputs produce the expected canonical string and a signature that verifies; ALSO cross-check with the Worker's
  own code: a small fixture generated by running the TypeScript `canonicalString` (e.g. `npx tsx`/node one-off script in `worker/`, output
  copied into a Rust test as constants), so a format drift would break the Rust test.

## Client API (blocking; `ureq` or similar small HTTP client with rustls — check the current crate version/API before using it)

```rust
pub struct WorkerClient { /* base url, identity, last timestamp */ }
impl WorkerClient {
    pub fn new(base_url: &str, identity: Identity) -> Result<Self, NetError>;  // https required except http://localhost / 127.0.0.1
    pub fn health(&self) -> Result<(), NetError>;
    pub fn register_device(&mut self) -> Result<(), NetError>;                  // POST /v1/devices {device_id, public_key_b64, display_name}
    pub fn create_crew(&mut self, name: &str) -> Result<CrewId, NetError>;
    pub fn create_invite(&mut self, crew: CrewId) -> Result<Invite, NetError>;  // {code, expires_at}
    pub fn join_crew(&mut self, code: &str) -> Result<CrewId, NetError>;
    pub fn members(&mut self, crew: CrewId) -> Result<Vec<Member>, NetError>;
    pub fn heartbeat(&mut self, req: &duoclip_presence::HeartbeatRequest) -> Result<duoclip_presence::HeartbeatResponse, NetError>;
    pub fn register_clip(&mut self, clip: ClipId, crew: CrewId, ttl_s: u32) -> Result<(), NetError>;
    pub fn upload_urls(&mut self, ...) / download_urls(&mut self, ...) / delete_clip(&mut self, clip) // per worker/SPEC.md shapes
    pub fn put_presigned(&self, url: &str, bytes: &[u8]) -> Result<(), NetError>;   // Content-Type application/octet-stream, exact Content-Length
    pub fn get_presigned(&self, url: &str) -> Result<Vec<u8>, NetError>;
}
pub enum NetError { Http { status: u16, code: Option<String> }, Network(String), InvalidResponse(String), Config(String) }
```
- Map the presence 409 to something `duoclip_presence::HeartbeatFailure::Stale409` can be built from; never log signed URLs, signatures or keys.
- Error messages for the user are in Portuguese; identifiers/comments in English.

## `duoclip-amigos.exe` (console tool, Portuguese)

```
duoclip-amigos configurar --url https://<worker> --nome "Nico"   # creates the identity file (keeps an existing key) and registers the PC
duoclip-amigos criar-grupo "Amigos do LoL"                       # prints the crew id
duoclip-amigos convidar [<grupo>]                                # prints an invite code (valid 24 h, 5 uses)
duoclip-amigos entrar <codigo>                                   # joins with a friend's code
duoclip-amigos grupos                                            # lists my groups (from a heartbeat snapshot) and their members
duoclip-amigos status                                            # identity (without secrets), Worker health
```
Group names/ids chosen by the user are kept in the identity file for convenience (`grupos: [{id, nome}]`).

## Tests

- Portable unit tests: signing/canonical string (incl. the TS cross-check fixture), identity file round trip (temp dir; secret never printed by
  `Debug`), URL validation, response parsing, timestamp monotonicity.
- Integration test `#[ignore = "needs a local Worker (npm run dev)"]` running the full friends flow (two identities: register, crew, invite,
  join, members, heartbeat snapshots) against `http://127.0.0.1:8787`. It may be run locally (local `wrangler dev` with local D1 migrations,
  as `worker/README.md` documents for `npm run test:crew`); **never against the deployed/remote Worker or R2**.

Required checks: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`,
`cargo check --workspace --all-targets --target x86_64-pc-windows-gnu`.

## Implementation notes

- **TLS backend: `native-tls` (Windows Schannel), not rustls.** `ureq` 3.4.2 is built with `default-features = false, features = ["native-tls"]`
  and the agent uses `TlsProvider::NativeTls` + `RootCerts::PlatformVerifier` (Windows certificate store). Reason: ureq's `rustls`
  feature pulls `ring`, whose build script needs a C compiler, and `cargo check --target x86_64-pc-windows-gnu` fails here with
  `failed to find tool "gcc.exe"`. Schannel is pure Rust bindings on Windows and passes that check. Consequence: on non-Windows hosts
  `native-tls` would use OpenSSL (the app is Windows-only, so not a concern; tests only use loopback HTTP). No gzip (not needed).
- **Crates added** (versions checked with `cargo info`/registry source): `ed25519-dalek` 3.0.0 (`SigningKey::from_bytes`, `Signer::sign`,
  key bytes from `rand::rngs::OsRng::try_fill_bytes`, so no extra RNG crate), `ureq` 3.4.2. Workspace `sha2`, `base64`, `hex`, `rand`,
  `zeroize`, `serde*`, `uuid`, `thiserror`, `tempfile` reused. `Cargo.lock` changes accordingly (shared file, separate commit per AGENTS.md).
- **Signing cross-check fixture** `tests/fixtures/worker_signing.json` was produced by compiling `worker/src` with `tsc` into a scratch
  folder and running the Worker's own `canonicalString`/`verifySignature` with WebCrypto Ed25519 on a throwaway seed (Ed25519 is
  deterministic, so Rust must reproduce the signatures byte for byte). The one-off script is not committed.
- **Status codes:** the client sets `http_status_as_error(false)` and no redirects, and builds `NetError::Http { status, code }` itself,
  reading the Worker's `{"error": "<code>"}` (only well-formed `[a-z0-9_]{1,64}` codes are kept). `HeartbeatFailure::from(&NetError)`
  maps any 409 to `Stale409`, other HTTP statuses to `Http(n)`, `InvalidResponse` and `Network` accordingly (`Config` errors map to `Network`).
- **Network error text** is a fixed Portuguese description per `ureq::Error` variant (never `Display` of the error, which can embed the URL).
  Presigned URLs are validated (https, or http on loopback) and never echoed. `Debug` of `Identity`, `Invite`, `SignedHeaders`,
  `PresignedChunk` and `PresignedObject` hides secrets/URLs/codes.
- **API additions beyond the sketch:** `UploadRequest`/`DownloadRequest`/`PresignedUrls`/`DeleteOutcome` types; `WorkerClient::{identity,
  identity_mut, into_identity, base_url}`; `normalize_base_url`; `validate_display_name`/`validate_crew_name` (same limits as the Worker:
  32 / 48 characters, no control or bidi-override characters). `register_device` sets `identity.registered`. `Invite.code` is a join
  credential: printed only by `convidar`. `with_clock` (doc-hidden) exists for tests.
- **Timestamps:** system clock in unix ms, bumped to be strictly greater than the previous request's (`signing::next_timestamp`).
- **Identity file:** `{device_id, display_name, secret_key_b64, worker_url, registered, grupos:[{id, nome}]}`; written to `<file>.tmp` and
  renamed over the target (mode 0600 on Unix; on Windows the per-user `%APPDATA%` ACL is the protection, as the SPEC says). Without
  `APPDATA` the default path falls back to `$HOME/.config/DuoClip/identidade.json`. The secret is zeroed after use where practical.
- **`configurar`:** keeps an existing key. Changing `--url` resets `registered` (a new server has never seen the key). A different `--nome`
  is refused once registered, because the Worker's `POST /v1/devices` does not update the stored name; delete the file for a new identity.
  The identity is saved before the network calls so the key is never lost.
- **`grupos`** sends one heartbeat (`game: null`, `active_crew: null`, `seq: 1`, `online_since_ms` = system clock ms) to get the snapshot,
  then `GET members` per group; members absent from the snapshot are shown as "offline". Side effect: this PC shows as online for about
  90 s, and (assumption, not tested) a running app announcing a larger `online_since_ms` could make this one-off heartbeat answer 409.
- **Group names are local only** (the Worker never returns them): groups joined with `entrar`/seen in `grupos` are stored as
  "Grupo <8 chars of the id>" until renamed by editing the file.
- **Tests:** 26 unit tests (signing incl. TS fixture, identity file, URL rules, response parsing, CLI parsing/group resolution),
  10 tests against an in-process loopback HTTP server (`tests/mock_server.rs`: exact requests, Ed25519 signature verification of every
  signed request, strictly increasing timestamps, error mapping, presigned PUT/GET with exact Content-Length, URL non-disclosure),
  and 1 `#[ignore]`d integration test (`tests/local_worker.rs`) for a local Worker at `http://127.0.0.1:8787` (fixed loopback address).
  The ignored test passed against `wrangler dev` with local D1 migrations; upload/download URL routes were not exercised against a real
  Worker because they need R2 credentials (`.dev.vars`), which were deliberately not used.
